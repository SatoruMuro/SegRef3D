# Local GPU SVG reference fixtures

Generated by `SegRef3D/tests/generate_svg_parity_fixture.py` using the unchanged
`SegRefMain` SVG exporter, parser and Qt rasterizer from source revision `d825ae4`.
The generator extracts and executes these methods with their real dependencies;
it does not duplicate their interpretation in a test oracle.

- `local-export.svg`: Local-generated Obj 1/2 regions, a hole, empty background,
  one-pixel line/column and Obj 20 at the corner.
- `empty.svg`: Local-generated empty slice.
- `legacy-shapes.svg`: rect/inline-style idiom from the existing Local SVG boundary
  test, with overlapping objects, polygon, polyline and a compound-path hole.
- `expected.json`: actual Local interpretation of those files, plus the UI palette.
- `decimal-parity.json`: 100 deterministic two-decimal polygons and actual Local
  raster bytes (base64), covering boundary rounding and self-intersections.
- `curve-parity.json`: 100 deterministic cubic/quadratic/smooth curves and their
  actual Local Qt raster bytes. Circle/ellipse cases are in `legacy-shapes.svg`.
- `migration/`: four Local-generated 6×5 masks. Their numbering follows the old
  natural DICOM filename order in `medical_source_fixtures.py`; that fixture's
  filenames oppose canonical physical slice order. `expected.json` records the
  current canonical order after reattachment to the original DICOM.

These are synthetic masks and contain no patient data. Regenerate from repository
root with `python SegRef3D/tests/generate_svg_parity_fixture.py` (NumPy, OpenCV,
PyQt6 and svgpathtools required). `test_lite_svg_parity.py` also calls the Local
parser on a newly generated Lite export and requires exact pixel identity for
all 20 objects, including holes and one-pixel regions.
